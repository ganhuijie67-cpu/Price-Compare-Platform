# 2. 需求文档

## 项目名称

**AI 商品比价与选购智能体**

## 一、项目背景

用户在购买数码产品时，通常需要在京东、淘宝、拼多多等多个平台反复搜索同一商品，对比价格、优惠券、店铺、售后和平台规则。

传统比价工具通常只提供价格列表，无法理解用户需求，也无法解释不同平台的优劣。用户仍然需要自己判断商品是否同款、是否为二手、是否为配件、是否为国行、价格是否异常。

本项目希望通过 AI Agent + RAG + 官方平台 API，构建一个可以帮助用户完成商品比价、商品推荐和选购问答的 AI 购物决策助手。

------

## 二、项目目标

本项目目标是实现一个可真实落地的小规模 AI 应用，支持二三十人到一百人以内使用。

核心目标：

```
1. 用户可以输入具体商品，系统自动完成多平台比价。
2. 用户可以输入购买需求，系统推荐合适商品。
3. 用户可以提出商品或平台相关问题，系统通过 RAG 回答。
4. 系统可以识别价格异常、商品风险并给出提醒。
5. 系统可以记录价格历史，并支持降价提醒。
6. 项目具备良好的工程结构，适合作为 AI 应用开发作品集。
```

------

## 三、目标用户

```
1. 想购买手机、电脑、耳机、平板等数码产品的用户
2. 不想反复打开多个平台比价的用户
3. 对商品参数、版本、售后政策不熟悉的用户
4. 需要购买建议和风险提醒的用户
5. 对价格波动敏感，希望设置降价提醒的用户
```

------

## 四、核心功能需求

## 1. 商品比价

### 功能说明

用户输入明确商品名称后，系统自动调用多个平台商品工具，返回不同平台的价格、店铺、商品链接、匹配度和风险提示。

### 示例输入

```
iPhone 17 Pro 256GB 国行
```

### 系统处理流程

```
1. 解析商品品牌、型号、容量、版本
2. 调用京东、淘宝、拼多多商品工具
3. 获取商品候选列表
4. 过滤手机壳、贴膜、二手、非目标容量等无关商品
5. 判断是否同款
6. 计算匹配度
7. 分析价格异常和风险
8. 按综合评分排序
9. 生成购买建议
```

### 输出内容

```
平台
商品标题
价格
券后价
店铺名称
店铺类型
商品链接
匹配度
风险标签
推荐理由
更新时间
```

------

## 2. 商品推荐

### 功能说明

用户不输入具体型号，而是输入购买需求，系统根据预算、用途、偏好推荐合适商品。

### 示例输入

```
预算 5000，想买拍照好、续航强的手机
```

### 系统处理流程

```
1. 解析用户预算、用途和偏好
2. 通过 RAG 检索选购知识
3. 生成候选商品列表
4. 调用比价工具查询候选商品价格
5. 综合价格、性能、售后、平台可信度进行排序
6. 输出推荐商品和理由
```

### 输出内容

```
推荐商品
推荐原因
适合人群
当前价格区间
推荐购买平台
风险提示
替代选择
```

------

## 3. RAG 选购问答

### 功能说明

用户可以询问产品知识、参数区别、平台规则、售后政策等问题，系统通过知识库检索并生成回答。

### 示例问题

```
256GB 够用吗？
iPhone Pro 和 Pro Max 有什么区别？
京东自营和天猫旗舰店有什么区别？
拼多多百亿补贴靠谱吗？
国行和港版有什么区别？
```

### 知识库内容

```
手机选购指南
存储容量选择指南
iPhone 型号对比
安卓旗舰机选购指南
平台售后政策
京东自营说明
天猫旗舰店说明
拼多多百亿补贴注意事项
国行/港版/美版区别
常见购买避坑指南
```

### 输出内容

```
自然语言回答
关键建议
引用来源
相关问题推荐
```

------

## 4. 价格异常与风险提示

### 功能说明

系统在比价时不能盲目推荐最低价，需要识别异常低价和潜在风险。

### 风险标签

```
价格异常偏低
疑似二手
疑似配件
容量不一致
版本不一致
非官方店铺
券后价不确定
售后风险
标题信息不足
```

### 示例输出

```
该商品价格比其他平台平均价低 18%，建议确认是否为全新国行、是否支持官方保修、是否需要使用优惠券。
```

------

## 5. 价格历史

### 功能说明

系统记录用户查询过的商品价格，展示价格变化趋势。

### 功能点

```
1. 记录每次查询的价格
2. 展示近 7 天 / 30 天价格变化
3. 显示当前价格是否接近历史低位
4. 支持按平台查看价格趋势
```

### 输出内容

```
当前价格
历史最低价
近 30 天均价
价格趋势
是否值得入手
```

------

## 6. 降价提醒

### 功能说明

用户可以为某个商品设置目标价格。当商品价格低于目标价格时，系统提醒用户。

### 示例

```
iPhone 17 Pro 256GB 低于 7500 元提醒我
```

### 系统处理流程

```
1. 用户设置目标价格
2. 系统保存提醒规则
3. Celery 定时查询商品价格
4. 判断是否低于目标价格
5. 如果满足条件，发送提醒
```

### 提醒方式

第一版可以先支持：

```
站内提醒
```

后续可扩展：

```
邮件提醒
微信服务通知
短信提醒
```

## 五、非功能需求

## 1. 合规要求

```
1. 不使用爬虫抓取电商页面。
2. 不绕过验证码、登录态或平台风控。
3. 商品数据优先来自官方开放平台 API。
4. API 审核前使用 Mock 数据开发。
5. 用户跳转购买时以平台实际页面为准。
```

------

## 2. 性能要求

```
1. 普通比价请求尽量在 3-8 秒内返回。
2. 热门商品查询使用 Redis 缓存。
3. 外部 API 超时时需要降级处理。
4. RAG 问答需要控制 top_k，避免响应过慢。
5. 系统需要支持小规模真实用户使用。
```

------

## 3. 稳定性要求

```
1. 平台 API 调用失败时返回缓存数据或友好提示。
2. 数据库异常时记录日志。
3. Agent 每个节点需要记录执行状态。
4. 后台任务失败需要重试。
5. 核心接口需要有超时控制。
```

------

## 4. 可扩展性要求

```
1. 平台 API 使用 Adapter 模式，方便增加新平台。
2. RAG 知识库支持新增文档和重新索引。
3. 商品推荐规则可配置。
4. 风险标签规则可扩展。
5. 后续可接入更多品类和更多平台。
```

------

## 六、第一阶段开发范围

第一阶段目标是跑通完整闭环，而不是一次性实现所有商业化能力。

### 第一阶段必须完成

```
1. FastAPI 后端基础项目
2. Next.js 前端基础页面
3. Mock 三平台比价数据
4. 商品比价接口
5. 商品推荐接口
6. RAG 问答接口
7. 商品卡片展示
8. 风险标签展示
9. 推荐理由生成
10. Qdrant 知识库检索
```

### 第一阶段暂不强制完成

```
1. 真实平台 API
2. 用户登录
3. 真实支付或返佣
4. 完整价格提醒通知
5. 大规模并发优化
```

------

## 七、第二阶段开发范围

```
1. 接入一个真实平台 API
2. PostgreSQL 存储商品和查询记录
3. Redis 缓存热门查询
4. 价格历史记录
5. 降价提醒基础版
6. Agent 执行过程展示
7. Docker Compose 部署
```

------

## 八、第三阶段开发范围

```
1. 接入京东、淘宝、拼多多多个平台
2. 优化同款匹配算法
3. 增加用户收藏
4. 增加用户偏好
5. 增加邮件或微信提醒
6. 上线给小范围用户测试
7. 完善 README、接口文档、架构图和项目复盘
```

------

## 九、项目亮点

```
1. 使用 LangGraph 实现多节点智能体工作流。
2. 使用 Tool Calling 调用比价、推荐、RAG 等工具。
3. 使用 Qdrant 构建商品选购知识库。
4. 使用 PostgreSQL + Redis + Qdrant 构建真实 AI 应用架构。
5. 区分实时价格数据和稳定知识数据。
6. 支持商品同款匹配和匹配度评分。
7. 支持价格异常识别和风险标签。
8. 支持价格历史和降价提醒。
9. 不使用爬虫，优先接入官方 API，强调合规性。
```

------

## 十、项目最终定位

本项目最终定位为：

> **一个集商品比价、智能推荐、RAG 选购问答、价格风险提示和降价提醒于一体的 AI 购物决策智能体。**

它不是简单的聊天机器人，也不是普通比价列表，而是一个可以理解用户需求、调用外部工具、检索知识库、分析风险并生成购买建议的真实 AI 应用系统。
